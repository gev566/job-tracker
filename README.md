# Трекер откликов

Небольшое приложение для учёта откликов на вакансии: компания, должность, ссылка, дата, статус и заметка. Данные хранятся в браузере (localStorage), сервер не нужен.

Сделано на React 19 и TypeScript, сборка — Vite, тесты — Vitest.

## Возможности

- Добавление, изменение и удаление откликов; форма с проверкой полей.
- Смена статуса прямо в списке: отправлен, просмотрен, собеседование, оффер, отказ.
- Поиск по компании, должности и заметке; фильтр по статусу; сортировка по дате.
- Сводка: сколько откликов всего и в каждом статусе.
- Статистика: график откликов по неделям за последние 2 месяца и воронка «отправлено → просмотрено → собеседование → оффер» с процентами.
- Напоминания: отклики без ответа дольше 7 дней подсвечиваются, их можно отфильтровать кнопкой «Пора напомнить».
- Экспорт в CSV для Excel и Google Таблиц, экспорт и импорт JSON (дубликаты по id не добавляются).
- Демо-данные: на пустом списке кнопка «Показать на примере» заполняет трекер вымышленными откликами.
- Тема: как в системе, светлая или тёмная — выбор запоминается.
- Адаптивная вёрстка, работает на телефоне.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev      # режим разработки, адрес покажет в консоли
```

Другие команды:

| Команда | Что делает |
|---|---|
| `npm test` | запускает тесты |
| `npm run build` | проверяет типы и собирает проект в папку `dist` |
| `npm run preview` | открывает собранную версию локально |
| `npm run lint` | проверяет код линтером |

## Структура

```
src/
  types.ts        типы: отклик, статусы, подписи статусов
  storage.ts      чтение и запись в localStorage, проверка данных из JSON
  filters.ts      фильтрация, поиск, сортировка и подсчёт по статусам
  filters.test.ts тесты для filters.ts и storage.ts
  analytics.ts    недели, воронка, правило «пора напомнить»
  csv.ts          выгрузка в CSV с экранированием
  analytics.test.ts тесты для analytics.ts и csv.ts
  theme.ts        выбор и сохранение темы
  sample.ts       демо-данные
  App.tsx         состояние приложения и связь компонентов
  components/
    Stats.tsx            сводка по статусам
    Analytics.tsx        график по неделям и воронка
    Filters.tsx          поиск и фильтр
    ApplicationForm.tsx  форма добавления и изменения
    ApplicationList.tsx  список откликов
```

## Как устроено

- Всё состояние живёт в `App.tsx`: список откликов, фильтр, строка поиска и состояние формы. Компоненты получают данные и обработчики через пропсы.
- Логика без интерфейса (фильтрация, подсчёт, разбор JSON) вынесена в обычные функции — их проще тестировать.
- Данные из localStorage и из импортируемого файла проверяются функцией `isApplication`: записи с неверной структурой отбрасываются.
- Список сохраняется в localStorage через `useEffect` при каждом изменении.
- Графики нарисованы обычными блоками с высотой и шириной в процентах — без библиотек, поэтому сборка остаётся лёгкой.
- Даты считаются по местному времени: строка `ГГГГ-ММ-ДД` разбирается вручную, чтобы не было сдвига на день из-за UTC.
- Тема хранится в атрибуте `data-theme` у `<html>`, цвета заданы CSS-переменными.

## Проверки на GitHub

- `ci.yml` — на каждый pull request запускает линтер, тесты и сборку.
- `deploy.yml` — при пуше в `main` делает те же проверки и публикует сайт.

## Публикация на GitHub Pages

В репозитории есть workflow `.github/workflows/deploy.yml`: при пуше в `main` он запускает тесты, собирает проект и публикует папку `dist`. Чтобы он заработал, в настройках репозитория откройте Settings → Pages и в поле Source выберите «GitHub Actions».
